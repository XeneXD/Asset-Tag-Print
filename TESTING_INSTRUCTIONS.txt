Testing Branch - Instructions for teammates

Branch: "Testing Branch"
Purpose: Run and test the current non-admin build and the recent fixes (app-local Configuration.xml fallback + startup copy attempt). Do NOT perform admin installs or elevated commands unless explicitly told.

Steps for testers (non-admin flow):
1. Open the solution in VS Code (do NOT run VS Code as Administrator).
2. Build the solution (dotnet build or via VS Code build command).
3. Run the app from the Debug configuration (F5 or run the built EXE from bin\Debug). Do not run elevated.
4. In the app, open Diagnostics (Diagnostics button) and verify:
   - "POS config (app local): Found" should show if the repo contains `Configuration.xml` (we added one to the project).
   - "POS config (ProgramData): Found" may be Missing if you did not run an elevated copy; that's expected for non-admin tests.
5. If you have a physical POS printer attached, test printing flows; otherwise verify that diagnostics list installed/printer queues and show expected status.
6. Report any functional issues or unexpected exceptions in the Diagnostics text. Include a screenshot if possible.

Notes and expectations:
- The app will attempt to copy the app-local `Configuration.xml` into ProgramData at startup; without admin rights that copy will fail silently or show a non-fatal warning (handled). This is expected in non-admin tests.
- Do NOT run any elevated PowerShell commands unless asked.
- If you want to revert the ProgramData file (only for admins), use the provided uninstall script in the repo or ask the maintainer.

What to test specifically:
- App starts without crashes.
- Diagnostics shows app-local Configuration.xml present.
- No unhandled exceptions in the UI during normal use.
- Print preview and barcode rendering behave as expected.

How to report back:
- Create an issue in the repo or reply in our team channel with:
  - Your OS/build (Debug/Release)
  - Diagnostics output (copy/paste the text)
  - Steps to reproduce any problem
  - Screenshot(s)

Contact: tag the repo owner or the QA lead when filing results.

Thank you — please test and report results on the branch "Testing Branch".
